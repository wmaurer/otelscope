Write a type test when the acceptance criterion is how the compiler treats a consumer's code: inference, assignability, rejection, overload selection, generic constraints, or a displayed public type. `pnpm typecheck` already covers a signature change whose compiler behavior is not under test. A runtime bug in generic code needs a runtime test, not a type test, when its type contract stays the same.

## Set up Tstyche

If the package has no `tstyche` devDependency, this skill adds it:

1. Run `pnpm add -D tstyche` in `packages/<pkg>/`.
2. Add `&& tstyche` to the end of the package's `test` script, so that `pnpm test` and `pnpm pre-push` run the type tests.
3. Put the tests in `packages/<pkg>/typetests/`, with this `tsconfig.json` beside them. Tstyche finds `*.tst.ts` files by default.

```json
{
    "extends": "../tsconfig.json",
    "compilerOptions": { "noEmit": true, "rootDir": ".." },
    "include": ["."]
}
```

Tstyche prints the compiler and the config it used, for example `uses TypeScript 6.0.3 with ./typetests/tsconfig.json`. TypeScript 7, the workspace compiler, has no JavaScript API, so Tstyche downloads TypeScript 6 on its first run, which needs network access. `baseline TSConfig` in that line means that no config includes the test file, so the strict options of `tsconfig.base.json` do not apply.

## Write the test

Read the nearby `.tst.ts` files and use their imports and assertion style. Use `expect(value).type.toBe<T>()` for structural equality, and choose the specific matcher for the contract under test, such as `toBeAssignableTo`, `toBeCallableWith`, or `toHaveProperty`.

Run one file with `pnpm exec tstyche <file name>` in the package. For a regression fix, confirm that the assertion fails against the type before the fix.

## Displayed types

Structural equality does not check what the editor shows on hover. For an internal alias or an intersection that leaks into a displayed type, assign the API's result to `never` to cause an error on purpose. Then match a short, distinctive part of its message with `@ts-expect-error`. Tstyche checks that the message contains that text.

```ts
test("make simplifies the displayed type", () => {
    const value = make({ value: "a" });

    // @ts-expect-error Type '{ readonly value: string; }'
    const displayed: never = value;

    void displayed;
});
```

Keep the expected text as short as it can be while it still tells the public type from the leaked type. Before you accept the test, restore the broken type for a moment and confirm that the match fails.

The task is complete when each intended compiler behavior in scope has an assertion that proves it, and `pnpm test` passes for the package.
