Measure a production bundle: minified, tree-shaken, and built from the current code. A size change is the difference against a base revision, measured with the same entry and the same command. The size of the current build alone is not a finding.

## Entry and tool

Measure one of these entries, and name it in the report:

- the package's own production build;
- a fixture: a small file that imports exactly the exports in question, through the entry points that a consumer imports.

Write a fixture inside the package, so that its imports resolve from the package's `node_modules/`, and delete it when you are done. When the entry points resolve to build output, build the package immediately before you measure. Otherwise you measure old output.

Use the bundler that the package's build already uses, with its own stats or metafile output. Where the package has no bundler, run esbuild through `pnpm dlx`, which needs no install. `<scratch>` is a directory outside the repository.

```bash
pnpm dlx esbuild <entry> --bundle --minify --format=esm --platform=browser --outfile=<scratch>/out.js --metafile=<scratch>/meta.json --analyze
node -e 'console.log(require("node:zlib").gzipSync(require("node:fs").readFileSync(process.argv[1])).length)' <scratch>/out.js
```

`--analyze` prints the size of each module in the output. The second command prints the gzip size in bytes.

## Stable comparison

1. Check out the base revision in a worktree outside the repository: `git worktree add <scratch>/base <base-ref>`. Use `HEAD~1` for the latest commit, or the merge base with the main branch for a whole branch.
2. Run `pnpm install` in the worktree. Build it if the entry resolves to build output.
3. Measure the same entry with the same command in both trees. Copy a fixture to the same path in both.
4. Report each difference that is not zero, as minified bytes and gzip bytes.
5. Run `git worktree remove <scratch>/base`, unless the user asked to keep it for more comparisons.

## Composition

Read the per-module sizes before you draw conclusions. Report the largest modules, the largest packages, and each module that the entry should not need. For a module that you did not expect, find the import chain that pulls it in. esbuild prints that chain for each module with `--analyze=verbose`, and the metafile lists the imports of each input under `inputs`.

The task is complete when the entry, the tool, and the base revision are named, every requested size or composition finding is reported with the paths of the generated files, and the base worktree is removed or kept as the user asked.
