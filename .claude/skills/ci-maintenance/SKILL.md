This skill is generated by project-setup from `agent-skills.config.js`. Do not edit it here: `pnpm skills:check` fails on any change, and `pnpm skills:sync` writes it again.

Map the trust boundary before you edit. This skill covers Actions event semantics, workflow security, permissions, action pinning, setup, untrusted inputs, timeouts, concurrency, and artifacts.

## Workflow

1. Decide if the task is a review or an implementation. A review reports findings with evidence and edits nothing. An implementation makes the smallest change that keeps the trust boundary.
2. Read every affected workflow, composite action, and caller. List all affected jobs and actions before you go on.
3. For each job, record the trigger, the actor and whether it can come from a fork, the workflow revision, the checked-out revision, the permissions, the credentials, and every external input and consumer. Inputs include artifacts, caches, outputs, pull request fields, refs, dispatch inputs, generated files, and called actions.
4. Read the current GitHub documentation for each decision that depends on platform behaviour. Workflows in the repository show local convention, not platform semantics.
5. Apply every rule that applies:
    - Set the workflow permissions to empty, and give each job the least permissions it needs.
    - Set up every job the same way. Take the pnpm version from `packageManager` in the root `package.json`, and use a Node version that its `engines` field allows. When the repository has a shared setup action, use it unless the job needs a different environment.
    - Run `pnpm install` with its lifecycle scripts. Its `prepare` script patches `tsc` and oxlint with the Effect rules. Without the patch, `pnpm lint` fails with `Unknown plugin: 'effecttsgo'`.
    - Give each job that runs code an intended matrix and a realistic timeout.
    - Pin each external action and reusable workflow to a full commit SHA, with the release in a comment. Check that the SHA belongs to that release upstream.
    - Decide the event, the checkout revision, and credential persistence together.
    - Pass untrusted expressions through environment variables. Validate and quote them before use.
    - Derive concurrency from whether a run is safe to interrupt.
6. For forks, privileged credentials, publishing, or data from another run, read [privileged-workflows.md](privileged-workflows.md).
7. Run `pnpm fmt`, then `pnpm fmt:check`. The formatter also checks the YAML in `.github/`. Read the complete diff, and list the behaviour that only a run on GitHub-hosted runners can test.

The task is complete when every affected job and caller has a recorded trust boundary, every rule that applies has evidence or a compensating control, the local checks pass, and the checks that need GitHub are listed. A review reports every failure with evidence. An implementation fixes every failure and contains only the intended behaviour.
