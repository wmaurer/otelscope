This skill is generated by project-setup from `agent-skills.config.js`. Do not edit it here: `pnpm skills:check` fails on any change, and `pnpm skills:sync` writes it again.

An upgrade changes every place that names a version, not only the lockfile. Take versions, commands, and compatibility points from the current repository.

## Discover

1. Read the affected `package.json` files and their scripts, `pnpm-workspace.yaml`, the CI workflows, and the test configuration.
2. Search for the dependency and for every current version, range, runtime input, engine constraint, patch, and compatibility claim.
3. Record each match as a development version, an engine minimum, a CI version, or a constraint that differs on purpose.
4. A package's runtime and test dependencies go in that package's own `package.json`. The root `package.json` holds only the workspace tools.
5. Choose the package-local branch or the coordinated branch.

Discovery is complete when every match is recorded.

## Package-local branch

Use this branch for one dependency of one package under `packages/`, when no row of [coordinated-upgrades.md](coordinated-upgrades.md) applies. Change only that package's `package.json`. If a coordinated row turns out to apply, switch branches.

## Coordinated branch

Read [coordinated-upgrades.md](coordinated-upgrades.md). Select every row that applies, and make all the edits of those rows before you install.

## Install and finish

Run `pnpm install` at the root after all edits. Read its warnings and the `prepare` output. A failed oxlint patch prints a warning and does not fail the install. Read the lockfile diff for specifiers, resolutions, duplicate transitive packages, peer warnings, patch hashes, and lifecycle scripts. Check with `pnpm why -r effect` that the workspace installs one version of `effect`. A successful install alone does not finish this review.

Run the checks that each selected row names, then `pnpm pre-push`.

The task is complete when a new search finds no unrecorded version, each manifest entry is in the right package, the lockfile has no unexplained change, and each check passes or is reported as not runnable.
