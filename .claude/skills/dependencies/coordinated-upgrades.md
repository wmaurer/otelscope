# Coordinated upgrades

Select every row that applies. Make all its edits before `pnpm install`, then run its checks.

| Change                                                         | Edit together                                                                                                                                                                                       | Checks                                                                                      |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `effect`, or an `@effect/*` package other than `@effect/tsgo`  | The entry in every `packages/*/package.json` that names one of them. They release together, so give them all the same version.                                                                      | `pnpm why -r effect` shows one version                                                      |
| `@effect/tsgo`, `oxlint`, `oxlint-tsgolint`, `@oxlint/plugins` | The exact versions in the root `package.json`, taken from the Supported Package Versions table in the `@effect/tsgo` README. `@oxlint/plugins` has the same version as `oxlint`. Never use a caret. | Read each patch line in the `prepare` output. Then `pnpm lint:sync --write` and `pnpm lint` |
| `typescript`                                                   | The root `package.json`. The `@effect/tsgo` README must list the new version as supported.                                                                                                          | `pnpm exec tsc --version` ends in `+effect-tsgo.<version>`                                  |
| pnpm                                                           | `packageManager` in the root `package.json`, and the pnpm setup in the CI workflows                                                                                                                 | A fresh `pnpm install`                                                                      |
| Node                                                           | `engines` in the root `package.json`, and the Node setup in the CI workflows. The floor stays at 22.18 or later, because the lint rules load as `.ts` files.                                        | `pnpm pre-push` on the new version                                                          |
| A package with install scripts                                 | The build allow-list in `pnpm-workspace.yaml`                                                                                                                                                       | A fresh `pnpm install`, then the tests of the package that uses it                          |
| A patched dependency                                           | The version, the `patchedDependencies` entry, the patch file, and the patch hash in the lockfile                                                                                                    | A fresh `pnpm install`, then the behaviour the patch exists for                             |
| A dependency with a `deps` entry in `repos.config.js`          | Its `tag` follows the installed version. A `force` version or a commit SHA in `tag` does not, so change it by hand                                                                                  | `pnpm deps:fetch`, then `pnpm deps:check`                                                   |

For a patched dependency, first test the new release without the patch. If the patch is no longer needed, remove its entry and its file. Otherwise refresh the patch with `pnpm patch`, and check that it applies and that the original problem still needs it.
